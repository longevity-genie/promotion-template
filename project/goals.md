# Goals

**Fill this in before drafting posts.** Every post should move people toward one or more of these outcomes, in priority order. While the list still contains `<...>` placeholders, an agent should stop and ask rather than inventing a strategy.

## What every post should drive

1. **`<primary action>`** — the one thing a stranger should do after reading. Try the product, clone the repo, run the demo.
2. **`<share action>`** — what a visitor makes that they can show someone else.
3. **`<contribute>`** — how a domain expert or developer actually helps: issues, corrections, nominations, patches.
4. **`<connect>`** — who you want introductions to, and why they would care.
5. **`<fund>`** — only if the project is looking. Residencies, grants, exhibition calls, not a generic "support us".

## What does not serve these goals

Name the framing that looks professional and helps nobody. A common failure: writing as if the project were a brochure or a knowledgebase to browse, when the actual ask is to try something, share a build, or correct a claim.
